# Dwelchain desktop frontend prototype

Статичний desktop-прототип платформи нерухомості на HTML5, CSS3 та Vanilla JavaScript ES Modules. Дані завантажуються з локального JSON; backend, реальна карта й надсилання форм не підключені.

## Локальний запуск

Запустіть статичний сервер у корені проєкту:

```powershell
python -m http.server 4173
```

Відкрийте `http://127.0.0.1:4173/`.

## Build

```powershell
npm run build
```

Команда створює:

- `dist/client` — HTML, CSS, JavaScript, JSON та локальні assets;
- `dist/server/index.js` — статичний worker для hosting-середовища.

## Маршрути

- `index.html` — головна: пошук, рекомендації, шлях користувача, Future Scope, карта, інвестиційний напрям, форма власника й контакти.
- `catalog.html` — каталог: базові й розширені фільтри, сортування, «Показати ще», loading/content/empty/error.
- `map.html` — локальна стилізована карта, синхронізований список, маркери й popup.
- `property.html?id=pechersk-skyline` — детальна сторінка об’єкта.
- `design-system.html` — внутрішня технічна сторінка компонентів; у публічній навігації її немає.
- `auth.html?mode=login` — вхід до демонстраційного кабінету.
- `auth.html?mode=register` — реєстрація з вибором ролі орендаря або орендодавця.
- `auth.html?mode=recover` — демонстраційне відновлення доступу.
- `account.html?role=tenant` — кабінет орендаря: огляд, збережені об’єкти, перегляди та профіль.
- `account.html?role=landlord` — кабінет орендодавця: огляд, власні об’єкти, заявки клієнтів та профіль.
- `property-editor.html` — frontend-форма додавання об’єкта; параметр `id` відкриває режим редагування.

Усі основні маршрути працюють після прямого відкриття та refresh. Параметри каталогу й карти зберігаються у query string.

## Особисті кабінети

Екрани входу, реєстрації, відновлення доступу та кабінетів є інтерактивним frontend-прототипом. Дані беруться з `assets/data/accounts.json`, не зберігаються у браузері та не надсилаються в мережу. Реальна авторизація, сесії, відновлення пароля, права доступу, завантаження фотографій і персональні записи мають бути підключені через погоджений backend та API на наступному етапі.

## Дані

`assets/data/properties.json` містить 12 демонстраційних об’єктів. Структура запису включає ID, угоду, тип, назву, район, орієнтир, валютні значення, кімнати, площу, поверх, поверховість, опис, фото, ознаки нового/рекомендованого об’єкта та параметри розширених фільтрів.

У mock-наборі навмисно є:

- довга назва й велика ціна;
- об’єкт без фотографій;
- об’єкт без координат карти;
- купівля й оренда;
- квартири, будинки й таунхауси;
- 11 приблизних позицій на стилізованій карті.

Фільтри: місто, район, карта/список, ціна, площа, кімнати, поверх, поверховість, меблі, ремонт, тварини, паркінг, балкон/тераса, тип будинку, забудовник, новобудова/вторинка.

## Frontend-форми

Реалізовано три доступні модальні форми:

- запис на перегляд;
- запитання менеджеру;
- пропозиція об’єкта власником.

Форми перевіряють required-поля, телефон, email, дату та невід’ємні числові значення. Вони не виконують `fetch`, не надсилають файли й не зберігають дані. Success-повідомлення прямо пояснює, що дані у прототипі не надсилаються.

У mock data зберігаються USD і UAH. Основна видима валюта — USD, поруч показується орієнтовний еквівалент у гривнях; для оренди вказано період «на місяць». Курс не розраховується у frontend і не оновлюється з мережі.

## Future Scope / P1–P2

На головній збережено погоджене майбутнє бачення: інвестиційний напрям, AI-асистент, call-центр, юридичний супровід, CRM, автоматизація, робота з агентами та сервіси для власників/інвесторів. У цьому етапі це презентаційний контент, а не реалізована бізнес-логіка.

До поточного frontend не входять backend, API, база даних, адмінпанель, авторизація, реальна CRM, AI, call-центр, юридична перевірка, реальна карта, платежі, аналітика, мобільна чи планшетна версія.
